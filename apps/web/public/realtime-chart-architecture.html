Real-Time Chart Data Ingestion, Streaming & Persistence Architecture

Decoupled Dual-Path Architecture: Hot-Path (Live Broadcast <10ms) & Warm-Path (Aggregated Batch DB Flush)

Hot Path: Low-Latency Stream

  • • No DB Dependency: Ingested ticks dipancarkan langsung ke client lewat SSE tanpa menunggu operasi SQL.
  • • Sub-10ms Latency: Client hanya menerima delta tick ({price, bid, ask}), mengupdate lilin aktif di memori canvas browser.
  • • Throttling: Broadcast dibatasi max 10 tick/detik per instrumen untuk mencegah DOM render thrashing.

Warm Path: Write-Behind Persistence

  • • Anti Write-Amplification: Dilarang melakukan INSERT SQL setiap tick. Ribuan tick dihimpun di RAM.
  • • Time-Window Aggregator: Membangun bar OHLCV (1m, 5m, 1h). Saat candle ditutup, bar disimpan ke queue.
  • • Batch Flush: Eksekusi single batch INSERT ... ON CONFLICT DO UPDATE setiap 5–10 detik via Drizzle ORM.

Cold Path & Crash Recovery

  • • Initial Viewport Window: Client saat load awal hanya meminta 250 bar terakhir (35KB) dari PostgreSQL.
  • • Infinite Historical Scroll: Saat digeser ke kiri, client memanggil ?to=earliestTs&limit=200.
  • • Gap Recovery: Worker mencatat last_synced_timestamp. Jika crash, worker menarik gap bar dari broker feed.
